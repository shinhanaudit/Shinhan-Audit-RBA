# 감사 체크리스트 - 언론 동향 반영

`fss-audit-checklist`로 만든 체크리스트가 금감원 공식 자료(검사업무안내서/제재/경영유의사항) 기준이라 최신 사건·사고를 놓칠 수 있다. 이 스킬은 언론 보도를 훑어 감사팀이 놓치면 안 되는 최근 이슈를 찾아 체크리스트에 추가 후보로 얹는다.

**전제조건**: `data/<업권명>/` 폴더와 확정된 체크리스트(표 또는 `checklist_<날짜>.md`)가 이미 있어야 한다. 없으면 먼저 `fss-audit-checklist`를 실행하라고 안내하고 중단한다.

## Phase 1: 검색 대상 확정

사용자 메시지 또는 직전 대화에서 업권명과, 있다면 특정 기관명(예: "신한은행")을 파악한다. 기관명이 없으면 업권 전반(예: "은행권")으로 검색한다.

검색 기간은 별도 언급이 없으면 최근 3개월로 잡는다 (감사 착수 시점 기준). 사용자가 기간을 지정하면 그에 따른다.

## Phase 2: 언론사 목록 확인

`config/press_sources.py`의 `PRESS_SOURCES` 딕셔너리를 읽어 검색 대상 언론사를 확정한다. 기본값은 다음 7개사다:

경향신문, 국민일보, 동아일보, 문화일보, 조선일보, 중앙일보, 연합뉴스

사용자가 "이 언론사도 추가해줘"라고 하면 `config/press_sources.py`에 `{"언론사명": "도메인"}` 한 줄을 추가하는 것으로 처리한다(코드 수정이지 임시 요청이 아니므로 파일에 반영). 특정 언론사만 이번 한 번 제외/포함해달라는 요청은 파일을 건드리지 않고 이번 실행 범위에서만 반영한다.

## Phase 3: 언론 보도 검색

`WebSearch`를 사용해 언론사별 또는 통합으로 검색한다. 쿼리 예시:

```
{기관명 또는 업권명} 금융감독원 검사 site:{도메인}
{기관명} 제재 site:{도메인}
{기관명} 금융사고 OR 소비자피해 OR 내부통제 site:{도메인}
```

- 언론사 수(7개 이상)만큼 개별 검색을 반복하면 비효율적이므로, 기관명+핵심 키워드 조합으로 먼저 범용 검색을 해보고, 결과에 잡힌 매체가 대상 언론사 목록에 포함되는지 확인하는 방식을 우선한다. 특정 언론사에서 결과가 전혀 안 잡히면 그 언론사만 site: 검색으로 보완한다.
- 검색 결과가 많으면(대략 15건 이상) 직접 하나씩 다 읽지 말고 `Agent`(subagent_type: `general-purpose`)에게 URL 묶음을 나눠 위임해 각 기사 요지(날짜/언론사/제목/핵심사실 1~2문장)만 요약해 오게 한다. 원문 왜곡 방지를 위해 서브에이전트에게도 "기사에 없는 내용을 추정하지 말 것"을 명시한다.
- 단순 홍보성 기사, 실적 발표, 인사 소식은 제외한다. 감사 관점에서 의미 있는 것만 남긴다: 금융사고, 소비자 피해/민원, 내부통제 실패, 규제 위반 의혹, 금감원 검사·제재 예고, 소송, 임직원 비위 등.

## Phase 4: 체크리스트 반영 후보 작성

찾은 이슈마다 기존 체크리스트 표 형식에 맞춰 후보 행을 만든다. 근거 컬럼은 반드시 언론사명+보도일자+기사 제목(요약)으로 표기하고, 금감원 공식 근거와 섞이지 않도록 근거 앞에 `[언론]` 표시를 붙인다.

```markdown
| 리스크 ID | 테마 | 소제목 | 리스크(1문장) | 감사항목(설계/운영) | 근거 |
|---|---|---|---|---|---|
| R9-005 | 소비자보호 | OO상품 불완전판매 의혹 | 2026.3월 보도에 따르면... | 관련 상품 판매 프로세스 표본점검, 민원 접수현황 확인 | [언론] 연합뉴스(2026.3.5.) "OO은행 OO상품 불완전판매 논란" |
```

- 리스크 ID는 기존 체크리스트의 다음 번호를 이어서 부여한다.
- 확인되지 않은 의혹·소송 중인 사안은 리스크 문장에 "~라는 의혹/보도가 있음"처럼 사실과 보도를 구분해서 쓴다. 금감원 제재처럼 확정된 사실인 것처럼 서술하지 않는다.

## Phase 5: 사용자 확인

후보 목록을 `[신규-뉴스]` 태그로 표시해 사용자에게 제시한다 (`fss-audit-checklist`의 Phase 5 태그 규칙과 동일한 체계를 쓰되, 언론發 신규 항목임을 구분하기 위해 태그를 다르게 표기한다). 사용자가 채택한 항목만 본 체크리스트에 `[신규]`로 편입하고, 이후 흐름은 `fss-audit-checklist`의 Phase 5(컨펌 루프)로 돌아간다.

관련 보도가 전혀 없으면 "최근 {기간} 내 {업권/기관} 관련 감사 관점의 유의미한 언론 보도를 찾지 못했다"고 있는 그대로 보고하고, 없는 이슈를 지어내지 않는다.

## 테스트 시나리오

**정상 흐름**: 체크리스트 확정 후 "언론 동향도 확인해줘" → 은행 업권 + 신한은행으로 검색 범위 확정 → 7개 언론사 기준 검색 → 감사 관점 이슈 2건 발견 → `[신규-뉴스]` 태그로 후보 제시 → 사용자가 1건만 채택 → 채택분만 본 체크리스트에 `[신규]`로 편입.

**이슈 없음 흐름**: 검색 결과 감사 관점에서 의미 있는 보도가 없음 → "찾지 못했다"고 보고하고 체크리스트는 그대로 유지.

**언론사 추가 흐름**: "한겨레도 넣어줘" → `config/press_sources.py`에 `"한겨레": "hani.co.kr"` 한 줄 추가 → 이후 실행부터 기본 목록에 포함.
